# Реклама на мониторах вагонов (Media Display): паки, анимации, мультивыбор

Рекламные изображения и анимации, которые крутятся на мониторах внутри вагонов
(81-717, 81-740, 760, Русич и т.д.), работают через **паки**.

- **Стандартный пак** (`default`) — картинки, которые уже есть в аддоне экранов
  (`materials/ms_screen/screens/advert/*`). Он всегда доступен и выбран по умолчанию.
- **Дополнительные паки** — отдельные аддоны со своими картинками/анимациями.

Рекламу выбирает **администратор**: меню `Q → Утилиты (Utilities) → Экраны вагонов
(Media Display) → Реклама на экранах`. **Можно отметить несколько паков сразу** —
реклама будет крутиться из объединённого пула всех отмеченных паков.

Команды консоли (админ или консоль сервера):

- `msd_setpack <id>` — выбрать один пак,
- `msd_setpack <id1>,<id2>[,...]` (или `<id1> <id2>` через пробел) — выбрать несколько паков,
- `msd_listpacks` — список найденных паков и что сейчас отмечено,
- серверный ConVar `msd_pack` — список id (через запятую; автоматически сохраняется,
  `FCVAR_ARCHIVE`).

Не-админам пункт меню виден только для просмотра — менять может только админ.
Неизвестные паки при выборе автоматически отбрасываются; если ни один не подошёл,
остаётся стандартный. Каждая реклама не показывается дважды подряд.

## Где должны лежать картинки

```
addons/<аддон-пак>/materials/ms_screen_packs/<id_пака>/…
```

Имя папки `<id_пака>` — это и есть id пака (латиница, без пробелов). Внутри пака:

- `.vmt` прямо в папке пака — статичные рекламы;
- любая вложенная подпапка (`advert/`, `ws/`…), где `.vmt` — независимые картинки —
  **статичные** рекламы;
- подпапка, где **все** `.vmt` имеют **номера** в имени и их не меньше двух
  (`001.vmt … 060.vmt`, `frame_1.vmt …`, `shot3.vmt …`) — **анимированная** реклама.

## Формат картинок: самый оптимизированный — DXT

Для экранов используется обычный материал `UnlitGeneric` (`$basetexture`). Формат
самих `.vtf` — любой поддерживаемый движком, но **рекомендуется сжатие DXT**
(аппаратное сжатие текстур):
самое крошечное и быстрое — **DXT1** (~1/4 памяти против несжатой RGBA8888):

- картинки **без прозрачности** (фон полностью закрашен) → `DXT1` — 512x256 = 64 КБ вместо 512 КБ;
- если нужна прозрачность → `DXT5` (в 2 раза больше DXT1, но несжатой всё равно в 4 раза меньше);
- мип-мапы не нужны (на мониторах картинка не уменьшается) — `Flags: BILINEAR + NOMIP + NOLOD`;
- разрешение любого размера, кратно 4; рекомендуемый размер — **512x256**.

Пример в аддоне `ms_screen_pack_example` уже сделан в DXT1 (см. `advert_*.vtf`,
`anim_demo/*.vtf`) — можно сверяться с ним.

## Анимированные рекламы (одна текстура, минимум нагрузки)

Анимированная реклама — это **один файл**: `.vtf`, внутри которого лежат несколько
кадров, и `.vmt` с прокси **AnimatedTexture**:

```
"UnlitGeneric"
{
    $basetexture ms_screen_packs/<id>/anim_demo
    $nolod 1
    $ignorez 1
    $vertexcolor 1
    $vertexalpha 1
    "Proxies"
    {
        "AnimatedTexture"
        {
            "animatedTextureVar"          "$basetexture"
            "animatedTextureFrameNumVar"  "$frame"
            "animatedTextureFrameRate"    "8"   // кадров в секунду
        }
    }
}
```

Как собрать такой `.vtf`: в VTFEdit импортируйте картинку-кадр с параметром
Frames > 1 (либо соберите многостраничный файл из последовательности кадров) —
все кадры окажутся в одном файле. Пропустите мипы («Flags: BILINEAR+NOMIP+NOLOD»),
формат — DXT1/DXT5, как и для статичных картинок.

Почему нагрузки от анимации нет:

- кадры крутит **сам движок** через прокси материала — ни серверу, ни клиенту
  не нужен Lua-таймер или пересылка кадра за кадром;
- сервер передаёт вагонам обычную строку с путём текстуры (как для статики);
- сервер лишь **один раз** при сканировании пака читает заголовок `.vtf`
  (число кадров) и указанный в `.vmt` `animatedTextureFrameRate`, чтобы
  выдержать длительность показа.

Реклама показывается **один раз**: сервер сменяет её через
`(кадры / fps) + hold` секунд, так что экран не зацикливает клип бесконечно.
Нюанс: прокси в движке цикличен, поэтому во время паузы `hold` картинка может
начать второй проход — если нужно строго один проход, задайте в регистрации
`hold = 0`.

Дополнительный контроль через регистрацию пака (необязательная):

```lua
if MSD_Packs then
    MSD_Packs.RegisterPack("<id>", "Название пака", "Описание", {
        -- ключ = имя анимированной текстуры/папки внутри пака
        ["anim_demo"] = { fps = 8, hold = 1 },
    })
else
    MSD_Packs_Pending = MSD_Packs_Pending or {}
    table.insert(MSD_Packs_Pending, {
        id = "<id>", name = "Название пака", desc = "Описание",
        opts = {
            ["anim_demo"] = { fps = 8, hold = 1 },
        },
    })
end
```

- `fps` — кадров в секунду (по умолчанию берётся из `.vmt`, а если там нет — 15);
- `hold` — сколько секунд держится последний кадр после проигрывания (по умолчанию 1).

Запасной способ (если не хочется собирать один VTF): **папка кадров** внутри
пака — подпапка, где все `.vmt` пронумерованы (`001.vmt, 002.vmt, … 010.vmt`).
Такие кадры разыгрывает клиент по своим часам (тоже «один раз», hold применяется
та же). Нумеруйте кадры с ведущими нулями, иначе при 10+ кадрах порядок
может не совпасть с числовым. Основной способ — одна анимированная текстура выше.

Технически при обоих способах: сервер лишь сообщает вагонам id рекламы,
кадры разыгрывает клиент (движок или локальные часы), поэтому лаги сети
не сбивают проигрывание.

## Как сделать свой пак

1. Копируем папку примера `ms_screen_pack_example`, переименовываем аддон и
   `materials/ms_screen_packs/example` в свои `<id>`.
2. Складываем в `materials/ms_screen_packs/<id>/` свои `.vtf` + `.vmt` (DXT1!),
   а для анимаций — папку с пронумерованными кадрами.

   Файл `.vmt` выглядит так:

   ```
   "UnlitGeneric"
   {
       $basetexture ms_screen_packs/<id>/advert_1
       $nolod 1
       $ignorez 1
       $vertexcolor 1
       $vertexalpha 1
   }
   ```

3. (необязательно) Регистрируем красивое имя и параметры анимаций (см. раздел выше):
   файл `lua/autorun/<любое имя>.lua` в аддоне пака
   (образец — `lua/autorun/msd_pack_example_register.lua` в примере).

4. Перезапускаем карту/сервер — библиотека сама просканирует материалы и пак
   появится в меню.

## Правила подсчёта

- В меню показывается число **реклам** пака (статики + анимации-папки; кадры анимации
  не считаются отдельными рекламами).
- Пак без единого файла рекламы в списке не показывается и не выбирается
  (даже программно через `msd_setpack`).
- Если отмеченный пак пропал (аддон удалили) — его просто нет в пуле; если не осталось
  ни одной рекламы — мониторы показывают сохранённую заглушку `inited_1`.

## Сервер / клиенты

Картинки рисуются на клиенте. Сервер **сам раздаёт файлы паков** подключающимся
игрокам (все `.vmt`/`.vtf` паков автоматически ставятся на раздачу при старте
карты и после выбора пака) — достаточно установить пак **только на сервере**
(в аддонах или Workshop). Пока файлы не скачались, вместо картинки будет
пустая (чёрная) область.

Ручной вариант не нужен, но при желании можно оставить в аддоне пака свой
`lua/autorun/server/*.lua` со списком `resource.AddFile`.

Стандартный пак ничего не требует — он уже внутри аддона экранов.

## Workshop

Паки работают и из Workshop-аддонов. Система ищет файлы тремя путями по очереди
(THIRDPARTY → GAME → WORKSHOP — все они видят контент смонтированных GMA),
поэтому в обычном случае достаточно положить материалы в аддон и зарегистрировать
пак, как в примере.

На случай, когда на какой-то сборке file-функции вдруг не видят содержимое
чужих GMA, есть **план Б**: список реклам прямо в таблице регистрации. Тогда
система строит список рекламы из неё, не полагаясь на скан файлов:

```lua
MSD_Packs_Pending = MSD_Packs_Pending or {}
table.insert(MSD_Packs_Pending, {
	id = "mypack",
	name = "Мой пак",
	opts = { ["myanim"] = { hold = 1 } }, -- параметры анимаций
	ads = {
		"advert_1", "advert_2",                      -- статичные картинки
		{ base = "myanim", anim = true, frames = 8, fps = 8 }, -- анимация
	},
})
```

- `frames` — число кадров в много-кадровом `.vtf` (тогда `anim` можно не указывать);
- `fps`/`hold` необязательны: fps возьмётся из регистрации (`opts`), hold по умолчанию 1;
- кадры движок всё равно крутит сам (прокси `AnimatedTexture` в `.vmt`), сервер
  использует подсчитанную по списку длительность (`frames / fps + hold`) для смены рекламы.

В пример-паке (`ms_screen_pack_example`) список `ads` уже заполнен — можно
копировать его как образец.
